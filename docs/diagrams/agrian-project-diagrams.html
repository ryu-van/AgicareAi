Project technical diagrams

Architecture and core flows for the Flutter mobile client and FastAPI modular monolith. Solid paths describe target behavior; the current local-only implementation is called out where material.

01 · architecture

Module boundary and trust boundary

One modular monolith keeps policy at the API boundary; external services are adapters, not feature-module dependencies.

02 · sequence

Production authentication and session recovery

Supabase owns sign-in; the API verifies access tokens. A refresh failure preserves drafts and requires a new sign-in.

03 · process

Safe, grounded RAG answer path

The answer is permitted only when published evidence, citation validation and safety policy all pass.

04 · data flow

Offline outbox and idempotent sync

The device retains the user’s work first; the API event ledger makes retries safe and returns conflicts explicitly.

05 · lifecycle state machine

Reminder lifecycle and device reconciliation

The server owns reminder state; a device notification is best-effort and is rescheduled after every sync or timezone change.
